# 寫程式

**任務：** "$ARGUMENTS"

開始前先用 Skill 工具載入 `alma:principles`，整個過程照它做。

開場把下面四個 Phase 的步驟逐字開成 todo 清單，做完一項勾一項。

## Phase 1：需求

1. 有 Jira 單就讀本單、父單、前後子單，只抽「要做什麼」：目標、人做的決定、驗收條件、已接受的風險。
2. 寫一句目標（有幾個寫幾個）＋來源。沒有需求來源時明講「目標是推測」，請使用者確認再往下。

## Phase 2：設計

只有新增元件、或改變某段流程的行為／順序（含並發、狀態轉換、排程互動）時才做這段；小修改直接跳 Phase 3。

1. grep 同類模組，找現成的做法和慣例。
2. 改動的是一段流程就畫文字流程圖，含改前與改後、主要路徑、錯誤路徑。
3. 牽涉聚合狀態就先列推導表（原則 5）。
4. 給使用者看目標、流程圖、做法，**等確認再寫**。

## Phase 3：實作

1. 做最小的改動。想加抽象、guard、try/except 時，先過原則 3、4。
2. 每條錯誤路徑寫完，問「這裡壞了誰會知道」（原則 6）。

## Phase 4：驗證

1. 從 Phase 1 的目標推測試，不照實作抄預期值（原則 8）。
2. 實際跑測試，貼出真實結果。失敗就照實說，不要寫「應該可以」。
3. 用 `/alma:review-mr` 的 Phase 3 檢查清單自己審一次 diff，列出看了什麼。
4. 交付：一句白話講做了什麼、怎麼驗證的、還有什麼沒做。不 commit、不 push，除非使用者要求。
